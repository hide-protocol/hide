# WinGet

WinGet is the one package manager here that cannot be published unilaterally:
it needs a pull request to `microsoft/winget-pkgs` and review by that project.
The three manifests below are generated by the release workflow into
`dist/winget/` with the real version and checksum, ready to submit.

Submitting is a deliberate step, not something the release workflow does on its
own. Publishing an unaudited encryption tool through a default Windows package
manager reaches people who will not read the warnings, so the decision to do it
belongs to a person.

To submit:

```powershell
winget install wingetcreate
wingetcreate submit --token <github-token> dist/winget
```

## Files

- `org.hideprotocol.hide.yaml` — version manifest
- `org.hideprotocol.hide.installer.yaml` — installer manifest (zip + portable)
- `org.hideprotocol.hide.locale.en-US.yaml` — description and metadata

## What the description must keep

WinGet strips formatting, so the warning has to survive as plain prose in the
`ShortDescription` and `Description` fields:

> Experimental and unaudited. A successful decryption proves the data was not
> altered; it does not prove who sent it. The wire format may change while the
> version is 0.x.
