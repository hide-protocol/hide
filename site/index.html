HIDE is experimental and unaudited. Do not use it for sensitive data. The protocol is a draft, no third party has reviewed the code, and the hybrid KEM tracks a moving IETF draft. See audit status.

HIDE — hybrid post-quantum file & message encryption

Human-friendly Identity & Data Encryption. HIDE is end-to-end encryption for files and short messages whose key encapsulation is quantum-resistant by construction: every content key is wrapped with X-Wing, a hybrid of X25519 and ML-KEM-768 as standardised in NIST FIPS 203 (ML-KEM), and every signature is a hybrid of Ed25519 and ML-DSA-65 from FIPS 204 (ML-DSA). A break of either half alone is not enough. The goal is to encrypt to a person, not to a key: the repository implements the file format engine, a hybrid signature scheme, and the machinery an identity needs to outlive a single key — device enrollment and revocation, forward security by erasure, an auditable history, and group messaging over MLS.

Source, specification and vectors: github.com/hide-protocol/hide (Apache-2.0). Machine-readable summary: llms.txt, llms-full.txt.

Install

Every binding calls the same Rust core through one C ABI; no language reimplements the cryptography. The CLI requires --experimental on every invocation.

cargo install hide-cli                  # command line, from crates.io
pip install hide-protocol               # Python
npm install hide-protocol               # Node / TypeScript
npm install @hide-protocol/wasm         # browser (WebAssembly)
gem install hide-protocol               # Ruby
dotnet add package HideProtocol         # .NET / C#
go get github.com/hide-protocol/hide/sdk/go   # Go, from source via cgo

Registry pages: crates.io · PyPI · npm · npm (wasm) · RubyGems · NuGet. Java and PHP are built from source. Desktop and portable builds are on the releases page; verify against SHA256SUMS.

age and libsodium are mature, audited tools, and age has offered a hybrid post-quantum recipient type since v1.3.0. If what you need is post-quantum file encryption to a key, use age: it is audited and HIDE is not. What HIDE adds on top is a signed multi-device identity with revocation, hybrid signatures on containers, forward security by epoch erasure, a transparency-log primitive and MLS group binding, all under one format. Help audit this

No third party has audited HIDE, and an unaudited encryption tool should be treated as broken until proven otherwise. Report findings through GitHub's private advisory as described in SECURITY.md; every finding is credited. There is no bounty, only credit and a fast fix.
